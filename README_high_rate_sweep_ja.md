# 高符号化率比較スクリプト

`sweep_high_rate_goppa_t_vs_rsrm.sh` は、BBGS + バイナリGoppa と RS + 短縮RMを、符号長 N と情報長 K を一致させて比較します。

## 高レート化の変更

従来の Goppa[60,6] (t=9) 固定をやめ、Goppaの訂正半径 t とブロック長を同時に変更します。

| t | BBGS側の内符号 | RS側の内符号 | RS外符号長 |
|---:|---|---|---:|
| 1 | Goppa[12,6,>=3] | RM(3,4)[16,15,2]（12情報bitに短縮） | 756 |
| 2 | Goppa[18,6,>=5] | RM(2,5)[32,16,8]（12情報bitに短縮） | 567 |
| 3 | Goppa[24,6,>=7] | RM(2,6)[64,22,16]（12情報bitに短縮） | 378 |

BBGS外符号長は1008シンボルです。各 t で N=1008*n_inner となり、RS側も同じ N になるように外符号長を選びます。情報長は K=6*k_AG、RS外符号の情報シンボル数は k_AG/2 とし、NとKを一致させます。

## 実行

```sh
cc -O2 -std=gnu11 -fopenmp -Wall -Wextra \
  unified_codes_matched_errors.c -lm -o unified_codes_matched_errors

chmod +x sweep_high_rate_goppa_t_vs_rsrm.sh
TRIALS=10 M_LIST="260 300 400 500 600 700 800" \
  INTERLEAVE_LIST="16 32 64 128 256" \
  BER_LIST="1 2 3 5 8 10 12 15" \
  BURST_LIST="64 128 256 512 1000" \
  ./sweep_high_rate_goppa_t_vs_rsrm.sh
```

本試験は `TRIALS=100` などに増やしてください。結果は実行ごとのディレクトリ内 `summary.csv` と個別ログに保存されます。

## 注意

- `t=1` はGoppaの設計最小距離が3で、訂正半径は1です。一方RM(3,4)の最小距離は2で、内符号の誤り訂正能力は同等ではありません。高レート端の探索用であり、内符号距離を揃えた比較ではありません。
- t=2,3でもRM内符号の設計距離はGoppaより大きく、同じ訂正能力条件ではありません。比較は連接方式全体の実装性能を見るものです。
- BBGS側はNewton syndrome + FR-VOTE、RS側はRM内符号復号 + RS復号です。
- インターリーブ幅は両方式で同じ値を使います。
- このビルドのRS復号器は冗長度 r が550を超える条件を処理できないため、その条件はスキップします。
- スクリプトは各条件の実行ログを保存します。CSVの値だけでなくログも確認してください。
- スモークテストは t=1,2,3 / M=700 / D=16 / 1 trial で完了しています。これは動作確認であり、性能評価の統計結果ではありません。
